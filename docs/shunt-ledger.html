Shunt Ledger

What it costs Claude to read a file directly, versus delegating the read to scripts/bulk-read and only keeping the answer in context.

n = 3 iterations per scenario fixtures: real Go source, labstack/echo v5.3.1 baseline model: claude -p --model sonnet real spend this run: $4.83 delegate: Spark/deepseek-v4.1-flash over HTTP run date 2026-10-13

How this was measured

Three scenarios, each run four ways, over the same question and the same file(s):

no-resume
Claude reads the file(s) directly, in a brand-new claude -p session. The cost of a one-off question with no prior context.
resume
Same question, chained into the same Claude session as the previous scenario via --resume. The cost of reading one more file in a session that's already open.
shunt
scripts/bulk-read delegates the question and file(s) to a separate model (Spark/deepseek-v4.1-flash) over the HTTP transport; only its answer lands in Claude's context. This kind has no Claude cost, only the delegate call.
shunt-live
A real claude -p session that calls scripts/bulk-read through Bash and answers from the result. This is the end-to-end cost a user actually pays for the shunt path.

Every number is the mean of 3 iterations (36 rows, all succeeded). Reported tokens for no-resume/resume/shunt-live are Claude's real input + cache_read + cache_creation usage summed over every turn of the session. For shunt they're a chars/4 estimate of just the delegate's answer text (a best case: it excludes the tokens a live session spends emitting the tool call that routes to it, which is what shunt-live measures). Read cost, not tokens. A large, roughly constant share of every Claude token count here (tens of thousands of tokens) is this project's own Claude Code system prompt and tool/skill/hook definitions, not the fixture file. That overhead is repriced far down once it's served from prompt cache. This is why shunt-live shows more context tokens (about 115k) than no-resume (about 65k): the live session takes several turns, and about 100k of its total is cache reads of the system prompt, with only 6 fresh input tokens per call. Its real cost is still 1.3x to 5x lower than no-resume/resume, so cost tracks reality better than tokens do.

Operating notes

Do not read shunt-live context tokens as a regression.

Shunt-live reports about 115k context tokens against about 65k for no-resume, but that figure sums every turn of the session, and about 100k of it is cache reads of the Claude Code system prompt (fresh input is about 6 tokens per call). Those cache reads are billed at a fraction of the fresh rate, so the real bill is lower: shunt-live costs 1.3x to 5x less than no-resume/resume depending on scenario, in exchange for being about 1.3x to 1.7x slower than no-resume end to end. The plain shunt row measures only the delegate call and has no Claude cost.

Speed depends on your provider, not on shunt itself.

The shunt timings above were measured against one delegate provider and model (Spark/deepseek-v4.1-flash over the HTTP transport). Different providers and models can be dramatically faster or slower for the same call, and gateway load varies over time. These numbers are a personal observation from one setup at one point in time, not a guaranteed baseline. Run evals/baseline-benchmark.sh against your own provider before trusting these figures to describe your own flow.
